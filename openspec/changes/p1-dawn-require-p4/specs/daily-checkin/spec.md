## MODIFIED Requirements

### Requirement: 破曉打拳 p1_dawn 加成

`p1_dawn` 是 p1 的特殊加成，固定 **+500 分**。系統 SHALL 滿足以下所有條件才接受 p1_dawn：

1. 同一邏輯日期已存在 **p1（打拳）** 打卡記錄（或上一邏輯日期的 p1，以涵蓋跨午邊界）
2. 同一邏輯日期已存在 **p4（子時入睡）** 打卡記錄（或上一邏輯日期的 p4，採與 p1 相同的判定範圍）

`p1_dawn` MUST NOT 佔用加權定課的 3 項上限，且每邏輯日最多 **1 次**。

p4「子時入睡」的時段不受強制限制（整天皆可打卡）；其說明文字為「子時（23:00–01:00）入睡」。

p1_dawn 的記錄一律由使用者**手動點擊**破曉打拳卡片完成；系統 SHALL NOT 在前置條件湊齊時自動補記。當 p1 與 p4 前置皆成立時，破曉打拳卡片解鎖為可點擊狀態，由使用者親自確認後記錄。

#### Scenario: 完成 p1 與 p4 後加打 p1_dawn

- **WHEN** 學員同一邏輯日已完成 p1（打拳）與 p4（子時入睡）
- **AND** 接著打 p1_dawn
- **THEN** 系統接受 p1_dawn 並 +500 分

#### Scenario: 已完成 p1 但未完成 p4 時被拒

- **WHEN** 學員當日已完成 p1，但尚未完成 p4
- **AND** 嘗試打卡 p1_dawn
- **THEN** 系統拒絕並回傳「需先完成子時入睡（p4）才能記錄破曉打拳加成。」

#### Scenario: 沒先打 p1 直接打 p1_dawn

- **WHEN** 學員當日尚未打 p1，直接呼叫 p1_dawn
- **THEN** 系統拒絕並回傳「需先完成打拳（p1）才能記錄破曉打拳加成。」

#### Scenario: 破曉打拳卡片在缺 p4 時呈鎖定態

- **WHEN** 學員已完成 p1 但未完成 p4
- **THEN** UI 顯示破曉打拳卡片但呈鎖定（不可點擊）態，並顯示「需先完成子時入睡」原因提示
- **AND** 完成 p4 後卡片解鎖、可點擊記錄

#### Scenario: 前置湊齊後由使用者手動記錄破曉打拳

- **WHEN** 學員先後完成 p1 與 p4，破曉打拳卡片解鎖為可點擊狀態
- **THEN** 系統 SHALL NOT 自動記錄破曉打拳
- **AND** 僅在學員親自點擊破曉打拳卡片後才記錄並 +500 分

#### Scenario: 跨午邊界以邏輯日判定 p1 與 p4

- **WHEN** 學員前一晚完成 p1 與 p4，隔日午前（00:00–11:59）嘗試記錄 p1_dawn
- **THEN** 系統以「今日或前一邏輯日」判定，p1 與 p4 皆成立，接受 p1_dawn

## ADDED Requirements

### Requirement: 收回 p4 連動收回 p1_dawn

當學員收回（undo）p4（子時入睡）時，若同一邏輯日已存在 p1_dawn 記錄，系統 SHALL 連動刪除該筆 p1_dawn 並一併扣回其分數（與既有「收回 p1 連動收回 p1_dawn」行為一致），因為 p1_dawn 的前置條件已不再成立。前端回溯確認彈窗 MUST 在此情境明確警示將一併收回破曉打拳。

#### Scenario: 收回 p4 連動移除當日 p1_dawn

- **WHEN** 學員當日已記錄 p4 與 p1_dawn
- **AND** 對 p4 發動回溯（undo）
- **THEN** 系統刪除 p4 與同邏輯日的 p1_dawn 兩筆記錄，並扣回兩者分數合計
- **AND** 回溯確認彈窗事先顯示「將一併收回今日的破曉打拳」的警語

#### Scenario: 收回 p4 但當日無 p1_dawn 時僅移除 p4

- **WHEN** 學員當日已記錄 p4 但未記錄 p1_dawn
- **AND** 對 p4 發動回溯
- **THEN** 系統僅刪除 p4，不影響其他記錄，亦不顯示連動警語
