# 覺醒體系開運親證班 — 管理者操作手冊

> 給大法師、大隊長、小隊長三種角色的完整功能與流程說明。

---

## 一、角色總覽

系統共有三種管理角色，各自負責不同的審核與管理工作：

| 角色 | 中文稱謂 | 主要職責 | 進入方式 |
|------|---------|---------|---------|
| Admin | 大法師 | 系統總管、終極審核、名單與分數調整 | 密碼登入「大法師密室」 |
| Commandant | 大隊長 | 大隊管理、二級審核終審、實體凝聚 | LINE 登入後自動顯示「大隊總部」分頁 |
| Captain | 小隊長 | 小隊照看、初級審核 | LINE 登入後自動顯示「隊長基地」分頁 |

> **重要原則**
> 1. 一個人可能同時擁有多個角色（例如大隊長同時是某小隊的隊長）。
> 2. 大隊長與大法師的權限有部分交集（都能做終審），可由任一方完成。
> 3. 小隊長只能管理自己小隊的成員與申請。

---

## 二、三種登入方式

### 1. 大法師（密碼登入）
- 在主畫面右上角找到「大法師密室」入口（或鍵入 `/admin`）。
- 輸入管理員密碼。
- 進入「AdminDashboard」管理後台。

> 密碼由系統管理員設定（環境變數 ADMIN_PASSWORD）。

### 2. 大隊長
- 用自己的 LINE 帳號登入（一般學員流程）。
- 若你的帳號在系統中被標記為大隊長（IsCommandant），底部分頁列會多出 **「大隊總部」**。
- 點該分頁即可進入。

### 3. 小隊長
- 同樣用 LINE 登入。
- 若你的帳號被標記為小隊長（IsCaptain），會多出 **「隊長基地」** 分頁。

## 三、大法師（Admin）操作指南

進入 **AdminDashboard** 後，上方會看到 6 個分頁：成員 / 任務 / 審核 / 九宮格 / 系統 / 課程。

### 3.1 成員分頁

#### A. 註冊模式切換
- **名單模式（roster）**：學員只能用助教預先匯入的 Email 註冊。
- **開放模式（open）**：任何人可自由註冊。
- 切換時請確認名單已匯入，避免無人能登入。

#### B. 名單批次匯入
1. 準備 CSV，欄位：`電話, 姓名, 生日, 大隊, 小隊, 是否小隊長, 是否大隊長`。
2. 在「成員 → 名單匯入」貼上 CSV 內容。
3. 系統會自動：
   - 標準化電話為 9 碼（去掉開頭 0）
   - 跳過標題列
4. 預覽匯入結果，確認無誤後送出。
5. 成功後可在下方搜尋確認。

#### C. 名單匯出
- 點「匯出 CSV」可下載目前名單與分數，作為備份或週報。

#### D. 成員搜尋與編輯
- 上方搜尋框可用 **姓名 / 電話 / Email / 大隊 / 小隊** 任一關鍵字搜尋。
- 點某成員 → 展開操作選單：

| 動作 | 說明 |
|------|------|
| 編輯 | 改大隊、小隊、角色（隊長/大隊長） |
| 分數調整 | 直接 ±分數，**必填原因**（會記錄在 AdminLogs） |
| 紀錄 | 查看該成員所有打卡與申請 |
| 刪除紀錄 | 刪除個別 DailyLog（會自動退回對應分數） |
| 刪除帳號 | 完全清除該成員所有資料（不可逆） |
| 切換管理員 | 把該成員設為大法師（或撤銷） |

#### E. 批量分數調整
- 用於活動結算或臨時加分（例如全員生日福利）。
- CSV 格式：`姓名或電話, 分數, 原因`。
- 點「預覽」確認對象正確 → 點「執行」。

#### F. 帳號清理
- **清除測試帳號**：移除 UserID 不是 9 碼電話格式的帳號（通常是開發測試）。
- **賽季重置**（限 2026/5/10 前）：清空所有分數、打卡、申請、課程報名等紀錄；保留帳號與名單。**之後即鎖定**，無法再執行。

### 3.2 任務分頁

#### A. 定課管理
- 對 d1–d8、p1–p5、p1_dawn、diet_*、wk1–wk4 設定：
  - **啟用 / 停用**：停用後學員看不到該卡片。
  - **分值覆寫**：填空白用預設值；填數字則用該值。
- 點「儲存」即生效（即時影響全體）。

#### B. 臨時任務管理
- 新增臨時加碼任務：填名稱、簡介、描述、分數、上限。
- 學員會在「旅伴週報」看到該卡片。
- 可隨時 **暫停 / 恢復 / 刪除**。
- 學員需上傳截圖申請 → 進入二級審核流程。

### 3.3 審核分頁

> 大法師可看到全系統所有審核中的申請。可作為「終審後備」處理大隊長未及時處理的案件。

#### A. 一次性任務終審
- 列出所有 squad_approved 狀態的申請。
- 可單筆或批次（多選）通過 / 駁回。
- 通過後即入帳（DailyLogs 新增、Score 增加）。

#### B. 臨時任務終審
- 與一次性任務相同流程，項目來自 TempQuestApplications 表。
- 可看截圖 + 小隊長備註。

#### C. 線上 / 實體凝聚總覽
- 切換 線上 / 實體 標籤：
  - **線上**：學員姓名、小隊、週次、狀態、備註
  - **實體**：小隊、日期、出席名單、是否大隊長到場、最終分數
- 不同狀態以不同顏色顯示（黃=待審、綠=通過、紅=駁回）。

#### D. 志工掃碼授權
- 設定 / 變更志工密碼。
- 志工在「親證曆 → 志工入口」輸入此密碼即可開啟掃碼器。

### 3.4 九宮格分頁
- 管理 5 種旅伴模板（事業/財富/情感/家庭/體能）。
- 可編輯每格的標題與描述。
- 修改後 **不會回溯影響已建立的學員九宮格**（學員九宮格在註冊時複製模板）。

### 3.5 系統分頁

#### A. 排行榜預覽
- 即時顯示 Top 學員，便於確認分數是否異常。

#### B. 操作日誌（AdminLogs）
- 顯示所有管理員行為：誰做了什麼、對誰做、結果、時間。
- 可作為審計依據。

#### C. 公告管理
- 新增公告（最多 300 字）→ 學員主畫面立即顯示。
- 可刪除舊公告。
- 多筆公告以「最新優先」排列。

#### D. 快照排程
- 顯示週快照（每週日凌晨）、月快照（每月 1 日凌晨）狀態。
- 若顯示「⚠️ 缺漏」，可手動點「立即執行」補上。

### 3.6 課程分頁
- 管理 SystemSettings 中的 CourseEvents：
  - 新增 / 編輯 / 刪除課程
  - 每堂課可設定：名稱、日期、時間、地點、是否開放報名、外部連結
  - 若設定外部連結，學員報名後會看到該連結（取代 QR Code）

## 四、大隊長（Commandant）操作指南

進入「大隊總部」分頁後，會看到以下區塊（由上至下）：

### 4.1 大隊狀態總覽
- 顯示各小隊的活躍率（過去 2 日有打卡的成員 / 全體）。
- 顏色標記：綠 ≥70%、琥珀 40–70%、紅 <40%。
- 點小隊可展開成員清單，看誰最近沒在動。

### 4.2 大隊成長曲線
- 過去 8 週分數變化折線圖。
- 用於確認整體士氣是否穩定上升。

### 4.3 排定實體凝聚
- 選擇小隊 + 日期 → 點「排定凝聚」。
- 排定後會出現在下方「已排定 / 審核中」清單，可取消。

### 4.4 凝聚審核中清單
- 顯示已排定但尚未終審的凝聚紀錄。
- 對小隊長已送出的申請，點「核准」會：
  - 計算最終分數（基礎 3000 + 全員 1000 + 大隊長 1000 = 最高 5000）
  - 為每位到場者批次入帳

### 4.5 一次性任務終審
- 列出所有 **squad_approved** 狀態的二級審核申請。
- 顯示：申請人、小隊、任務名、約訪對象、日期、截圖、小隊長備註。
- 可：
  - 全選 / 多選 → 批次通過或駁回
  - 單筆通過 / 駁回（可附終審備註）

### 4.6 臨時任務終審（新功能）
- 列出所有 squad_approved 的臨時加碼申請。
- 顯示：申請人、小隊、任務 ID、日期、截圖、小隊長備註。
- 點「核准」即入帳；點「駁回」可附理由。

### 4.7 匯出大隊成員 CSV
- 一鍵下載所屬大隊全員的姓名、分數、連續天數、活躍狀態。

> **注意**：大隊長無法看到別的大隊資料，只能管理自己所屬大隊。

## 五、小隊長（Captain）操作指南

進入「隊長基地」分頁後，會看到：

### 5.1 小隊成員總覽
- 列出所有隊員姓名、分數、連續天數、最近打卡日。
- 點「分數調整」會跳到顯示，但實際只能由大法師操作（小隊長為唯讀）。

### 5.2 小隊成長曲線
- 過去 8 週分數變化。

### 5.3 隊員角色職稱指派
- 為隊員分配角色：副隊長 / 抱抱 / 衡衡 / 叮叮1號 / 叮叮2號 / 樂樂。
- **只是顯示用標記**，不影響分數。

### 5.4 隊員九宮格管理
- 看每位隊員的 9 格進度。
- 若隊員誤勾某格 → 點該格旁的撤銷按鈕：
  - 清除該格紀錄
  - 若該格觸發過連線，會自動扣回連線分數（系統會跳警告）

### 5.5 線上凝聚審核（一級）
- 列出待審申請：隊員姓名、週次、備註。
- 點「核准」→ **直接入帳 +1000 分**（無需終審）。
- 點「駁回」→ 可附理由。

### 5.6 一次性任務初審
- 列出所屬小隊待初審的一次性任務申請。
- 顯示申請類別：
  - **戲劇進修（o2_1~o2_4）**：點「✅ 核准（直接入帳）」會直接通過 + 入帳（一級審核）。
  - **其他二級任務（o1, o3-o7）**：點「✅ 初審通過」→ 送至大隊長終審。
- 都可駁回並附理由。

### 5.7 臨時任務初審（新流程）
- 列出隊內待初審的臨時加碼申請。
- 顯示：申請人、任務 ID、日期、截圖、學員備註。
- 點「通過，送終審」→ 進入大隊長 / 大法師終審。
- 點「駁回」→ 可附理由（學員可重新申請）。

### 5.8 實體凝聚當日流程
依當日狀態，畫面會自動切換：

| 狀態 | 顯示內容 | 可操作 |
|------|---------|-------|
| 尚未排定 | 「尚未排定實體凝聚」 | （無，由大隊長排定） |
| 已排定（未來） | 顯示預定日期 | （等到當日） |
| 已排定（當日） | 顯示掃碼 QR + 已掃名單 + 隊長自報到按鈕 | **送出審核** |
| 審核中 | 「審核中…等待大隊長終審」 | （等待） |
| 已核准 | 顯示「每人 +X 分」 | （無） |
| 駁回 | 顯示駁回原因 | （由大隊長重排） |

**當日操作流程**：
1. 出示 QR 給隊員掃碼。
2. 自己也記得 **點「我也報到」** 完成隊長簽到。
3. 大隊長若到場，請大隊長同樣掃碼（系統會自動加成 +1000）。
4. 結束後，點「送出審核（交大隊長終審）」。

## 六、二級審核流程圖

### 申請狀態流轉

```
申請建立 → pending（待小隊長處理）
   ├─ 小隊長核准 → squad_approved（待大隊長/大法師終審）
   │     ├─ 終審核准 → approved（已入帳） ✅
   │     └─ 終審駁回 → rejected（學員可重新申請）❌
   └─ 小隊長駁回 → rejected（學員可重新申請）❌
```

### 任務審核級別總覽

| 任務 | 一級審核（小隊長） | 二級審核（大隊長/大法師） |
|------|------|------|
| wk3_online 線上凝聚 | ✅ 直接入帳 | — |
| wk3_offline 實體凝聚 | ✅ 出席驗證 | ✅ 終審計分 |
| 戲劇進修 o2_1 ~ o2_4 | ✅ 直接入帳 | — |
| 一次性任務 o1, o3-o7 | ✅ 初審 | ✅ 終審 |
| 傳愛 o7 | ✅ 初審 | ✅ 終審 |
| 臨時加碼任務 | ✅ 初審 | ✅ 終審 |

### 顏色色碼

| 顏色 | 狀態 | 學員可否操作 |
|------|------|------|
| 灰色 | 未申請 | 可申請 |
| 琥珀 | pending（待初審） | 可取消 |
| 藍色 | squad_approved（待終審） | 不可動 |
| 綠色 | approved（已入帳） | 不可動 |
| 紅色 | rejected | 可重新申請 |

## 七、常見管理場景

### 場景 1：學員回報「我打卡了但沒拿到分數」
1. 大法師開「成員 → 搜尋該學員 → 紀錄」。
2. 看 DailyLogs 是否有當日紀錄。
3. 若 **有紀錄但分數不對**：手動 ±分數調整，原因填「修正定課計分異常」。
4. 若 **沒紀錄**：請學員重新打卡（可能是瀏覽器網路斷線）。

### 場景 2：學員申請被誤駁，希望恢復
1. 學員可直接重新申請，**不需後台復原**（系統設計如此，已駁回不可逆）。
2. 若是分數異常需補回，由大法師用「分數調整」直接補上。

### 場景 3：學員轉隊
1. 大法師開「成員 → 搜尋該學員 → 編輯」。
2. 改大隊、小隊、角色。
3. 儲存。
4. 學員下次打開 App 即看到新隊。

### 場景 4：批量新增名單
1. 整理 CSV：`電話, 姓名, 生日, 大隊, 小隊, 是否小隊長, 是否大隊長`。
2. 大法師「成員 → 名單匯入」貼上。
3. 預覽 → 送出。
4. 通知學員可用 LINE 登入（會綁定到匯入的電話）。

### 場景 5：賽季結束清空資料
- **限 2026/5/10 前** 可在大法師「成員 → 賽季重置」執行。
- 5/10 之後系統自動鎖定，需透過程式碼手動處理。

### 場景 6：突發加分活動（例如生日福利）
1. 整理 CSV：`姓名或電話, 分數, 原因`。
2. 大法師「成員 → 批量分數調整」貼上。
3. 預覽 → 執行。

### 場景 7：學員找不到 LINE 登入入口
- 確認他用的是同一支手機綁定的 LINE 帳號。
- 若已換手機需重新綁定 → 由大法師在「成員 → 編輯 → 解除 LINE 綁定」處理。

### 場景 8：實體凝聚當日大隊長忘了到場掃碼
- 隊員可仍照常掃碼。
- 凝聚送終審後，大隊長確認後手動補上「大隊長到場」標記再核准（系統允許大隊長以申請紀錄為依據自行判斷）。
- 若已入帳但漏算大隊長加成 → 大法師用「分數調整」補上 1000/人。

### B. 操作日誌（AdminLogs）

每筆紀錄包含：
- **action**：動作類型（例：`temp_quest_add`、`member_transfer`、`bonus_final_approve`）
- **actor**：執行者姓名
- **target_id / target_name**：被操作的對象
- **details**：細節（JSON 格式）
- **result**：結果（success / error）
- **created_at**：時間戳

可在「系統 → 操作日誌」查看，或匯出 CSV 作審計。

### D. 緊急事件處理建議

1. **大量學員無法登入** → 檢查 RegistrationMode 設定、Supabase 服務狀態。
2. **分數計算異常** → 暫停相關定課（任務分頁 → 停用），由工程師排查 SQL function。
3. **學員資料外洩疑慮** → 立刻變更 ADMIN_PASSWORD，檢查 AdminLogs。
4. **快照失敗** → 系統 → 快照排程 → 點「立即執行」，多次失敗請聯絡工程師。
